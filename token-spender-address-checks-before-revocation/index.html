Token Spender Address Checks Before Revocation

To verify a token spender address before revoking approval, match its full address to trusted project documentation on the same chain, then inspect that chain’s explorer.

By Crypto Readout EditorialNov 25, 2026 · 07:28 UTC4 min read#621deb

To verify a token spender address before revoking approval, match the full address and network in the approval entry to trusted project documentation, then inspect the address on that same chain’s block explorer.

The spender is an address on one chain

An ERC-20 allowance gives a spender address permission to use a token on a particular chain. The project name in an approval list can help you recognize an entry, but the address identifies the contract that holds the permission. Names and logos can be copied, so use them as clues rather than as your confirmation.

Start by connecting the wallet that holds the approval and opening its approval list. Select the network where the approval appears, then find the relevant token and copy the spender’s full address from that row. Keep the network in view: an Ethereum address and a Base address associated with the same protocol name refer to separate contracts.

An approval event records an allowance change in transaction logs. revokecash’s explanation of approval event logs adds context for understanding what that record means; revokecash can also help locate the approval row whose spender you need to check.

Next, find the project’s official app or contract documentation and look for its reference address for the same network. Compare the entire address, character by character. A partial match, a familiar name, or an address listed for another chain is not a match.

Then open the copied address in the block explorer for that network. For an Ethereum approval, use Etherscan and inspect the Ethereum address; for a Base approval, use an explorer showing Base. The explorer can show the address, contract code, and transaction history. Verified source code helps identify what code is published at that address, but it is one clue, not an endorsement that the contract is safe.

Consider a wallet entry labeled with a protocol you use on Ethereum. You copy its spender address and compare it with that project’s official Ethereum contract reference. If the addresses match, you have confirmed that the approval points to the documented Ethereum contract. If you instead find a Base address with the same protocol name, that does not confirm the Ethereum spender: it is a separate contract on a separate chain. Check the Ethereum address in Etherscan and review its contract details and history. If the project documentation names a different Ethereum address, stop and investigate why before revoking or taking another action.

A changed address can have an ordinary explanation, such as a patched or separate contract, but the protocol name alone cannot tell you which contract received this approval. Look for a project statement that explains the specific address and network, and compare it with the approval entry. When the address differs from the trusted reference or remains unexplained, do not act on the label alone. Resolve the mismatch for that contract first. Once you have confirmed which spender has the allowance, you can make a more informed decision about whether to revoke it.

Related

How do I find the spender address?

Read the spender address from the approval row for the relevant token, and note the network selected in the wallet. Copy the full address and open it in that network’s block explorer. The explorer entry should be for the same chain as the approval you are checking.

Does verified source code mean a spender is safe?

No. Verified source code helps identify the code associated with an address, but it does not certify that the contract is safe. Compare the full address with trusted project documentation for the same network, and investigate any difference you cannot explain.
