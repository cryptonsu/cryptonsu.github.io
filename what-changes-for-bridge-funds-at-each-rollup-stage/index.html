What Changes for Bridge Funds at Each Rollup Stage?

Rollup stage 0 vs stage 1 vs stage 2 changes who controls bridge funds: operators, a proof system with a council override, or code with a longer exit window.

By Crypto Readout EditorialNov 27, 2026 · 22:38 UTC4 min read#f6e8a7

Stage 0 vs Stage 1 vs Stage 2 changes who can alter a rollup bridge, who can prove an exit, and how long users have before an upgrade takes effect. The higher the stage, the less power sits with a small set of operators and the more protection comes from proofs and enforced delays.

For Base bridge users, the stage label describes who can control the contracts behind funds locked on Ethereum or Base. Before moving a large balance, assess Base bridge safety before moving size against the relevant contract and withdrawal details; the stage is one part of that decision.

Who can upgrade the bridge, and who can prove an exit?

At Stage 0, a small key set can upgrade bridge contracts without a delay. Those contracts hold or release assets as users move them between Ethereum and the rollup. Whoever controls the upgrade keys may be able to change that logic, including redirecting locked funds. A user’s balance can be unchanged on screen while the rules governing its release change underneath it.

At Stage 1, anyone can submit fault proofs to challenge an invalid state and users can pursue an exit without relying on the operator to approve it. That makes the proof system a route around operator control. But a Security Council remains an override. L2BEAT’s framework requires at least eight council members and a 75% threshold; members should be mostly external. The council can still intervene, so proof-based exits do not put bridge control entirely beyond human hands.

At Stage 2, proofs are permissionless and the council’s override is limited to bugs that can be proved onchain. The distinction is who gets to decide: at Stage 1, a council can override the normal process; at Stage 2, its authority is tied to a verifiable fault. Base reached Stage 1 in 2025, so funds in the Base Bridge contract still rely on its Security Council for emergency action.

Think of the stages as different rules for changing a vault’s lock. Stage 0 gives the keyholders broad discretion. Stage 1 adds a public way to challenge a bad opening, while retaining a council override. Stage 2 narrows that override to a fault the chain can verify.

How long do users have to exit before an upgrade?

Stage 2 requires at least 30 days for users to leave before an upgrade takes effect. That window matters only if your withdrawal can finish before the deadline. A native withdrawal can involve a seven-day challenge period, which uses up part of the time available. Start the withdrawal as soon as an upgrade is queued, rather than waiting to see whether the change affects you.

For an illustrative case, imagine funds in a rollup bridge when a Stage 2 upgrade is queued with a 30-day delay. The funds are still in the same bridge after the queue; what changed is that the clock is running before new contract rules take effect. If the native exit requires seven days for its challenge period, that time comes out of the window. Congestion, a delayed start, or a challenged withdrawal can leave less room. Check the actual upgrade schedule and withdrawal state, and leave a margin rather than treating day 30 as a target.

Stage 0 suits users who accept operator control and do not plan to leave large sums in the native bridge. Stage 1 is a stronger fit when permissionless proofs and an exit path matter, while accepting that the council can still override. For large balances held long-term, Stage 2 offers the strongest of these three controls: permissionless proofs, narrowly limited overrides, and at least 30 days to exit before upgrades. Compare the exit window itself, not just the stage label.

Which stage is Base on L2BEAT?

Base is Stage 1. That means fault proofs allow independent challenges and exits, while the Security Council retains emergency authority. Check L2BEAT’s current project assessment when making a decision, since stage ratings can change as contracts and governance change.

Does rollup stage matter when using a fast bridge like Across?

Yes. A fast bridge can make funds available before a native withdrawal finishes, but it does not change the rollup’s upgrade controls or proof rules. Stage still matters to the underlying bridge and settlement risk. For a large transfer, consider both the fast route’s terms and the rollup’s native exit window.
