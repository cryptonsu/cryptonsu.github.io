How Many Confirmations Does a Token Swap Need? It Depends on the Chain

How many confirmations does a token swap need to be final? There is no universal count; the right milestone depends on the blockchain and how much certainty you need.

By Crypto Readout EditorialNov 22, 2026 · 19:42 UTC4 min read#d19c51

A token swap has no universal confirmation count: its finality depends on the blockchain and the settlement level you need.

When you submit a swap, the network processes the transaction and may include it in a block. That inclusion is the first confirmation. Each later block adds another confirmation, which can make a reorganization less likely on chains that use this kind of growing confirmation depth. Protocol finality is a separate, chain-defined milestone.

For a Matcha swap, the route across liquidity sources does not change the blockchain’s finality rules. The article on what Matcha swap support can do explains which status questions support can address.

What happens between a swap and finality?

A swap first needs to be included in a block; after that, the network’s rules determine how confidence in that block grows and when it is final.

Imagine you exchange one token for another on Ethereum using Matcha swap. You approve the transaction, Ethereum executes it, and a block includes it. A wallet or block explorer may then label the transaction “confirmed.” That label can mean the transaction is in a block; it does not necessarily mean Ethereum has finalized the block.

On proof-of-stake Ethereum, validators finalize checkpoints through supermajority links. At least two-thirds of staked ETH must support the relevant checkpoint links. So the protocol’s finality condition is not a fixed number of confirmations chosen for each swap. Later blocks provide additional confirmation depth, while checkpoint finality is a distinct consensus milestone.

Wallets and explorers may show different status labels or update them at different points. Read the status in context: “included” or “confirmed” can describe block inclusion, while “finalized” refers to a chain-level condition. Treating those as separate milestones helps you decide whether a swap is ready for the next step you have in mind.

The same word can cover different stages across networks. Polygon has its own block and checkpoint behavior. Arbitrum and Optimism process transactions on Layer 2 and also settle transaction data on Ethereum, so an early Layer 2 status and a later settlement status are not identical. A swap on one of these networks does not use a universal count that can be carried over from Ethereum or another chain.

How do I check whether a swap is finalized?

Check the transaction on the network where the swap happened, and identify which status the chain or explorer is reporting.

Start with the transaction hash in your wallet or explorer. Confirm that it is included in a block and that the transaction succeeded. Then look for the relevant chain’s finality indicator or documentation. On Ethereum, that means distinguishing a block confirmation from protocol-finalized status. On Arbitrum or Optimism, check which Layer 2 or Ethereum settlement stage the status represents; on Polygon, use the status for Polygon’s own network.

How long to wait depends on what you plan to do with the result. For a small swap you are simply checking in your wallet, inclusion may be enough to see that the token balances changed. If you are relying on the transaction for a consequential payment, accounting entry, or another action that assumes the result will not be reorganized, wait for the stronger finality milestone appropriate to that chain. The value at stake and the cost of acting on a reversed transaction both matter.

There is no one confirmation number that makes every token swap final. Use the chain’s own status and finality rules, rather than treating a wallet’s “confirmed” label as a universal guarantee.
