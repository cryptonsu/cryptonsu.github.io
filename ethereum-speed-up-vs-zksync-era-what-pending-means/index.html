Ethereum speed-up vs zkSync Era: what pending means

Why can't you speed up a pending zkSync Era transaction like on Ethereum? Era ignores priority tips, so check the explorer and refresh MetaMask instead.

By Crypto Readout EditorialNov 25, 2026 · 07:43 UTC3 min read#a5cb5f

You usually can’t speed up a pending zkSync Era transaction like an Ethereum transaction because Era does not use priority fees to decide which transaction goes first. The sequencer processes transactions on Layer 2, and a long “pending” message in MetaMask often means the wallet display is stale or the transaction never reached the sequencer.

Ethereum tips and Era’s sequencer work differently

On Ethereum, a signed transaction enters a public mempool, where block builders can choose transactions with higher tips. MetaMask’s “Speed up” sends a replacement with the same nonce and a higher maxPriorityFeePerGas, the EIP-1559 tip that can make the transaction more attractive for inclusion.

zkSync Era uses a sequencer to collect and execute transactions on Layer 2. Its fee rules do not use priority fees, so raising the tip does not give a replacement transaction an advantage in the queue. When comparing the same swap, wallet, and network conditions, a higher tip can help on Ethereum’s fee-priority market; the same change on Era does not change the sequencer’s ordering. Think of it as joining a line: offering a bigger tip helps only if the line uses tips to decide who moves forward.

That difference matters when you swap through SyncSwap: a higher fee in MetaMask may not make the swap happen sooner. The zksync era dex topic helps explain where SyncSwap’s swap takes place and why a wallet’s “pending” label may not tell you whether the trade already finished.

Check the transaction hash before changing wallet data

A transaction accepted by the sequencer is generally processed on Layer 2 within seconds. After it is included in an L2 block, the batch can move through Ethereum stages: committed, proven, then executed. The L2 result is available after processing; waiting for those later Ethereum stages does not prevent you from using the swapped tokens on Era.

Take a SyncSwap trade that MetaMask still calls pending. If the Era explorer shows its hash as processed or included on L2, the swap has run; the wallet’s activity display is stale. Confirm the transaction status and token balance on Era before trying again, so you do not submit a duplicate swap.

Now keep the same wallet and swap, but change one condition: the explorer cannot find the hash. That means the transaction was not recorded there, so the sequencer may never have received it. In that case, clear MetaMask’s activity and nonce data, then submit the swap again. Do this only after checking the explorer; clearing activity data resets the wallet’s local transaction history, not the blockchain record.

If the explorer shows the transaction is still pending, wait and keep checking its status. A replacement with the same nonce and a higher fee still cannot buy priority on Era. It may instead fail with “nonce too low” if the original transaction has already been processed.

Related questions

Can I cancel a transaction on zkSync Era?

You cannot cancel a transaction that has already been processed on L2. Check the explorer first. If the hash is still pending, MetaMask’s cancel option may attempt a same-nonce replacement, but Era does not prioritize it through a higher tip, so cancellation is not guaranteed.

Why does MetaMask show a nonce error on zkSync Era?

A nonce error often means the account has already used that transaction number. The original may have reached the sequencer and completed even though MetaMask still shows pending. Check the hash and account activity on the Era explorer before resubmitting.
