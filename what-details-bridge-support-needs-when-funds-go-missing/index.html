What Details Bridge Support Needs When Funds Go Missing

What details does bridge support need for a missing transfer? Send the source hash, both chains, addresses, token, amount, UTC time, status and message ID.

By Crypto Readout EditorialNov 25, 2026 · 14:42 UTC4 min read#af4b33

Prepare a ticket support can trace with the source transaction hash, both chain names, wallet addresses, token, amount, UTC time, app status and any message ID shown. Use this list when funds have left the source wallet but have not appeared at the destination. Monad bridge transfers supported assets between Ethereum and Monad, so name both ends of the route clearly.

  • Source transaction hash: Copy the full hash from wallet activity or Monad bridge history. The hash uniquely identifies the source transaction and can be searched on that chain’s explorer, such as Etherscan for Ethereum.
  • Source and destination chains: Write the network names in order, from where the transfer began to where it should arrive. A route tells support which chain’s transaction to inspect and where to look for the destination side.
  • Sender and recipient addresses: Include both full wallet addresses. These show which account initiated the transfer and which account should receive it; don’t rely on a wallet nickname or shortened address.
  • Token and exact amount: Name the asset and copy the amount as displayed. Include the token contract address when available, since token names can be reused and the contract identifies the specific asset.
  • UTC timestamp: Give the time the source transaction was made or submitted, converted to UTC. This helps support narrow down the relevant activity when reviewing chain records.
  • Status label and screenshot: Record the exact status shown in the app and attach a screenshot that includes it. The label captures what the interface reported when you checked; the screenshot preserves that context.
  • Message ID or sequence, if shown: Add any cross-chain identifier displayed by the app or explorer. Wormhole transfers use an emitter chain, emitter address and sequence number; Axelar GMP calls are tracked by message ID on Axelarscan.

On-chain identifiers give support a traceable starting point

A bridge transfer has a source transaction and cross-chain data that can help identify its progress. The source transaction hash is the first lookup key: support can use it to find the transaction on the source chain, then use the route and any bridge-specific identifier to follow the transfer. Think of the hash as a parcel’s initial receipt; the message ID or sequence helps identify its handoff.

For a Monad bridge transfer, the chain names and source hash establish which route and transaction to examine. The app’s displayed status and any message ID add context to that record. A concrete example is the Monad bridge, where the supported route between Ethereum and Monad makes naming both chains essential to tracing the transfer.

Send the identifiers as plain text in the ticket, alongside the screenshot. Don’t post the full set publicly: a public transaction hash can be searched, and public posts about missing transfers can attract scammers who monitor them for potential targets.

Public transfer posts can draw fake support accounts

A scammer may reply to a public “transfer missing” post or send a direct message while pretending to be bridge support. The request may be for a seed phrase, private key, or a signature to “sync” or recover the transfer. Those requests are not part of providing the on-chain details in this checklist. Never share a seed phrase or private key, and do not sign a message for someone claiming to be support. A real support ticket can be built from public on-chain data and the status shown in your app.

Related

Where do I find the transaction hash in my wallet?

Open the wallet’s activity for the source transaction and copy its transaction hash. If the activity entry links to an explorer, open it and copy the hash shown on the transaction page. Monad bridge history may also show the source transaction. Copy the full value so support can search it accurately.

How long should I wait before contacting bridge support?

There is no single wait time that can be determined from the transaction hash alone. Use any timing guidance shown by the app, and include the UTC time and current status when you contact support. That gives support the timing context without relying on an estimate.
